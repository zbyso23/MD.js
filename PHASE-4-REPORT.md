# MD.js Reborn v0.4 — Phase 4 implementation report

**Artifact:** local F4 extension of the attached user project and the existing MD.js Reborn v0.3. **Runtime dependencies:** zero. **JavaScript target:** browser ES6/classic scripts (no `import` or build step). **Security model:** HTML generated by fixed serializers; no raw HTML pass-through. Mermaid renderer v0.3 retained.

## Delivered

| Feature | F4 status | Limitations |
|---|---|---|
| GFM task lists (`- [x]`, `- [ ]`) | Implemented | HTML checkboxes deliberately disabled, not editable |
| GitHub alert blockquotes | Implemented | NOTE/TIP/IMPORTANT/WARNING/CAUTION, extended mode |
| Reference-style links and images | Implemented | One-line definitions, optional quoted title; bounded definitions |
| Footnotes and backlinks | Implemented | Inline footnote contents; indented continuation lines joined with spaces; not full CommonMark footnote block grammar |
| Naked web autolinks | Implemented | HTTP(S) and `www.`; intentionally does not claim complete GFM email autolink grammar |
| HTML entities | Implemented subset | Named entity allowlist + valid numeric references; no full HTML named-entity table |
| Backslash line breaks | Implemented | Explicit `\\` + LF maps to `<br>` |
| Single/double-tilde strikethrough | Implemented in extended | Other delimiter edge cases not fully CommonMark-conformant |
| GFM tables + escaped pipes | Retained / tested | Complex mixed backticks and nested syntax incomplete |
| Diagrams + reader UX | Retained from v0.3 | Mermaid subset deliberately limited |

## Not implemented / deliberately postponed

- Entire CommonMark 0.31.x spec; exact GFM spec compliance. The parser remains pragmatic and has known nonstandard edge cases.
- Full HTML named entity database and full email autolinks.
- Arbitrary trusted HTML (explicitly not enabled).
- Full math/TeX rendering: not credible to implement safely as a tiny utility.
- Deep CommonMark tight/loose list parity, full delimiter-stack algorithm, all link-title variants.
- F4.5 interactive charts, sortable tables, code-copy toolbar (see separate proposal).

## Verification

- Baseline v0.3: 117/117 passing automated Node tests.
- v0.4: 161/161 passing automated Node tests (44 new tests; including task lists, references, footnotes, alerts, hostile HTML/URL probes).
- JS syntax: all source/test scripts and inline scripts from browser demo files checked with Node 22.16.0.
- Headless browser smoke: **NOT VERIFIED**. Chromium stalled in the environment and was terminated after a 14-second cap. Do not treat Node tests as proof of browser compatibility.
- Security: fixed HTML output, escaped text, protocol validation; attack corpus passing. **No claim of formal XSS proof or independent security audit.** Application CSP and browser testing remain necessary; embedding untrusted external HTTP images may trigger network access.

## Payload and performance (local microbenchmark)

Environment: Node.js v22.16.0, one machine, same synthetic repetitive text workload; best of five runs; no isolation from host scheduling; payload sizes below are Markdown UTF-8 lengths; parsed output may be longer. **Only indicative** and not a fair industry benchmark.

| Payload | v0.3 parse | v0.4 parse | Relative change |
|---|---:|---:|---:|
| 4 KiB | 0.74 ms | 1.43 ms | unstable small-input noise |
| 16 KiB | 1.16 ms | 1.37 ms | +18% |
| 64 KiB | 4.16 ms | 5.89 ms | +42% |
| 256 KiB | 16.78 ms | 20.78 ms | +24% |

Parser source size: v0.3 24,415 B raw / 7,545 B gzip, v0.4 **32,644 B raw / 9,837 B gzip** (source only; no CSS, diagrams, UX). Expansion of **+2,292 B gzipped** is the incremental source cost.

These results are not yet a conclusion about speed at scale. Run repeated interleaved runs on fixed hardware, add real Markdown corpora, and separately measure the cost of reference/footnote-heavy documents. F4 was prioritized for portability and usefulness over maximum throughput.
