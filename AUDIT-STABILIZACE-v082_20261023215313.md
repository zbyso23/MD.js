## Opravené defekty a změněné soubory

### A — Obnovení disketového řadiče (FDD) — potvrzený bug, opraven

**Soubor:** `optional/pc/PC-Floppy.js`  
**Regresní test:** `optional/pc/tests/stabilization-floppy-snapshot.test.cjs`

Původní `FDD765.restore()` obnovoval jen obsazené sloty. Pokud snapshot říkal „A: prázdná“, ale instance mezitím obsahovala disk A:, starý disk tam zůstal. Při chybném obrazu B: se také mohla nejprve změnit A: a až poté vyhodit chyba; to porušovalo princip atomického importu. Pole `status` se exportovalo, ale při obnově se neobnovilo. Oba nové testy **prokazatelně selhaly na původním kódu**.

**Oprava:** nejprve dekódovat a ověřit obě média i metadatový stav, až potom v jednom kroku nahradit sloty. Prázdný slot zůstane prázdný, zaznamenaný stav řadiče se obnoví. Import chybného obrazu neprovádí částečnou výměnu disket. Snapshot zůstává v dosavadním formátu.

### B — Testy po UX Shell v0.8.2 — potvrzený zastaralý test, opraven

**Soubor:** `optional/pc/tests/test_universal_browser.py`

Původní skript používal `locator('#boot').click()`, ale UX Shell tlačítko přemístil do zavřeného panelu **Diagnostika**. Browser hlásil interception/timeout. Test nyní skutečně otevírá odpovídající drawer, kliká do něj, zavírá jej a analogicky zachází s panelem **Snapshot**. Neobchází UX přes JS `.click()`.

### C — Release gate — nedostatečné zahrnutí testů, opraveno

**Soubor:** `package.json`

Přidáno `test:stabilize` pro první kombinovaný sanity gate a rozšířeno `test:release` o `test:runtime:browser` a `test:ux:shell`. **Runtime aplikace stále nemá žádné npm závislosti.** Node a Playwright jsou jen pro vývojáře/testy.

### D — Přenositelnost osobního ZX testu — opraveno

**Soubor:** `zx/tests/e2e/test_universal_zx_browser.py`

Výchozí ROM byla v testu navázaná na cizí `/mnt/data/seBasic321.rom`. Test nyní přednostně použije vlastní `zx/roms/zx48.rom` v osobním archivu a stále umožňuje `MDJS_TEST_ZX_ROM` přepsat cestu. Ve veřejné verzi bez ROM zůstává **explicitní SKIP**, který je nutno sledovat.

### E — Dokumentace — zpřesněna

Na začátek přidán současný stav v0.8.2, přesné příkazy pro testy a upozornění na `file://`, CRT aspect a licenční limity. Staré release poznámky zůstávají zachovány jako historie (nelze je číst jako současný stav).

## Zjištěné otevřené problémy

### P1 — Významná rizika před další funkcionalitou

1. **CRT geometrie:** v HGC 720×348 `raw 1×` moderní čtvercové pixely deformují kresby navržené pro historické CRT. Navrženo oddělení `Raw` / `Historical 4:3` bez úpravy VRAM a zachování přepínačů `1×/2×/Fit`. Dosud nerealizováno.
2. **Další negativní snapshot testy:** PC CPU/video/BIOS/ZX importy mají mít testy poškozených, přesahujících a nekonzistentních polí. Před akceptací nových formátů vyžadovat přesný roundtrip a fail-closed chování.
3. **Reálné `file://`:** aktuální CI Chromium zakazuje samotnou navigaci na lokální soubor, takže výsledný test opaque-origin nesmí vystupovat jako přímé ověření lokálního souboru. Je potřeba ruční nebo nezakázané automatizované ověření Chrome/Firefox/Edge.
4. **Dlouhé reálné běhy:** testy úspěšně dobootují DOS a ověřují příkazy, ale dosud neprokazují hodiny bez degradace, deterministický snapshot během I/O a více cyklů reset/import/export s konzistencí FAT12.
5. **Chromium-only UX:** přístupnost z klávesnice, zoom 200 %, snížený pohyb, mobilní DnD, chybové návraty a procesní využití paměti nejsou plně certifikovány.

### P2 — Úklid a kvalita testovací infrastruktury

- Některé browser testy přepisují **Git-tracked screenshoty**. V auditovaném vstupu byly již tři screenshoty změněné proti `HEAD`; při našem E2E se změnily i další. V tomto předaném ZIPu jsou **všechny screenshoty zachované původními bajty ze vstupního archivu**. Navrženo ukládat budoucí výstupy do ignorovaného test-output adresáře a nepřepisovat reference.
- Několik browser runnerů napevno zadává `/usr/bin/chromium`, což je na některých strojích nepřenositelné. Převést na `CHROMIUM_BIN` a Playwright fallback.
- Některé historické texty/roadmapy zůstávají časově neaktuální; opraven je aktuální vstup do README, ale historické milníky se nemají mazat.
- Stávající 513 testů není rozčleněno do formální matice riziko → důkaz → konkrétní invariant. Zvlášť u CPU a FDD je žádoucí nezávislý oracle, ne jen test vlastního chování stejnou implementací.
- CI workflow se primárně zaměřuje na ZX; samostatně sjednotit gate pro Markdown, PC, ZX a Blocks s právně čistými testovacími assets.

## Doporučený následující postup (stabilizace, nikoli Phase 3)

1. Zmrazit aktuální funkční baseline: `npm run test:release` bez nových HW funkcí, všechny chybové reporty s reprodukcí.
2. Rozšířit **negativní** testy importu/obnovy state a ochrany dat (PIC/PIT/DMA, video, FDD, ZX).
3. Přidat typizovanou browser test matrix pro UX a skutečné `file://` na lokálním stroji.
4. Testovat dlouhé běhy DOS a varianty FDD/boot + referenční video obraz, zvlášť HGC aspect.
5. Uklidit screenshot artefakty, sjednotit test reporty a teprve pak zvažovat vydání označené za stabilní.
